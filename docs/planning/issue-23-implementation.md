## Transport contracts

Shared Zod schemas and `FinancialCorrection`, `CreditSource`, `AllocationRelease` types are in `packages/contracts/src/index.ts`. All routes require a ready current session and existing Origin/CSRF checks on POST. Input money is an exact nonnegative decimal in the source/charge currency; output is exact integer minor-unit strings. Never convert currencies or round. Every command includes UUID `commandId` and nonempty `reason`; retain the same command after an uncertain response. Changed actor/payload reuse conflicts. Current action/patient/clinic/own-work authority is rechecked before replay.

| POST route under `/api/billing/:patientId` | Additional input / behavior |
| --- | --- |
| `/credits` | `chargeId, revision, finalCharge`. `discounts` or manager; explicit lower final charge, retained signed adjustment. Excess allocated funds are explicitly released as credit, never refunded. |
| `/allocation-releases` | `settlementId, chargeId, amount`. `billing.edit` or manager. Explicitly releases part of an existing allocation; charge due rises and traceable credit becomes available. Reuse through existing `/settlements` with credit-only allocation creates no new receipt. |
| `/reversals` | `settlementId`. `reversals` or manager. Corrects an entire erroneous new-money receipt, invalidates its remaining direct and downstream allocations and credit sources, restoring debt. No cash refund. Refuses already-reversed or already-returned funds; a refund cannot be erased by claiming those funds never existed. Other original credit used in a mixed settlement remains intact. |
| `/refund-requests` | `sourceId, amount`. `refunds` or manager. Retained proposal against a visible credit source; no reservation or money movement. |
| `/refund-approvals` | `requestId`. `refunds` plus manager/concerned-own-work doctor authority. Staff cannot approve; unassigned deposit approval requires manager. Approval does not reserve funds. |
| `/refunds` | `requestId`. `refunds` or manager; requires retained approval. Rechecks available source credit and consumes it exactly once, retaining approval ID. Manager/doctor can request, approve and execute their authorized refund themselves using explicit commands; no different-person requirement. |
| `/cancel-plan` | `planId, revision, charges:[{chargeId,revision,finalCharge}]`. Requires `discounts`, active clinical patient scope, doctor eligibility and `clinical.read`/`plans.finalize`. Every started charge must have an explicit final amount no greater than current charge. Financial adjustments/releases and retained cancelled plan revision commit atomically. Original starts/completions/visits/payments remain; no automatic refund. Non-doctor financial managers can adjust finances but cannot cancel clinical care. |
| Existing `/reconcile` | Retains accepted-revision/revision/reason checks. Renewed accepted price changes on invoiced charges now append a correction linked to the original invoice; immutable invoice content remains. Reduction below allocated funds still requires explicit release/credit first. Successful prior commands remain replayable. |

Doctors cannot approve unassigned deposits or another performer's funds. Current revocation/disabled/historical-only rules remain enforced by identity.
