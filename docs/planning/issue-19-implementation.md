## Implementation decisions

Files follow Routes → Controller → Service → Repository, shared Zod transport types and tenant RLS. Raw binary HTTP requests avoid multipart staging and its abandoned-body files; route-scoped bounded parsing accepts PDF/JPEG/PNG only, max 20,000,000 bytes, four bodies at once per API process. Image validation uses exact pinned sharp 0.35.5 (Node >=20.9; current Node24), PDF parsing uses pdf-lib 1.17.1. Installed with exact lockfile pins, npm reported zero vulnerabilities. These are content parsers within the approved stack, no new service/infrastructure. Sources consulted: [sharp input](https://sharp.pixelplumbing.com/api-input/), [pdf-lib PDFDocument](https://pdf-lib.js.org/docs/api/classes/pdfdocument), [PDF parser source](https://github.com/Hopding/pdf-lib/blob/master/src/core/parser/PDFParser.ts), [Express upload limits](https://expressjs.com/en/resources/middleware/multer/). Multer was considered; it is unnecessary for this documented single-binary transport.

Private generated keys live outside web serving. The adapter writes exclusively and syncs file contents before publication; authorized reads verify retained length/checksum. Metadata versions and command receipts are insert-only for the runtime role. Reservation rows precede disk writes and expire after ten minutes. Clinic-scoped transaction locks serialize quota admission, replacement conflicts, publication and cleanup. Quota sums all retained bytes and reservations, including removed/replaced bytes. Failed writes are reconciled under lock before discard, so an uncertain committed publication cannot lose its object. If access/database/storage failure prevents immediate cleanup, the durable reservation remains; the next authorized clinic upload discards expired unreferenced objects before admission. This is lazy recovery, not a background worker or a claim of power-loss/restore rehearsal.

Clinical action and patient access are both required. Financial manager authority is intrinsic. Ordinary doctors cannot receive opaque financial/mixed bytes that cannot enforce own-work scope. Staff without separate active clinical access cannot receive opaque financial files whose clinical fields cannot be filtered. This deliberately applies the approved deny-unseparable-content rule; no metadata assertion is trusted as proof of file content ownership. Mixed mutation requires mixed action capability plus both underlying action/content scopes. No reclassification endpoint exists. Historical-only accounts and historical URL guesses cannot use active file routes; #18 separately owns historical grants/cutoff snapshots and will consume retained versions. This ticket does not implement or claim acceptance of #18.

Signed acceptance evidence optionally links a current authorized clinical/mixed attachment version through the existing treatment lifecycle API. The treatment transaction validates patient/clinic/version/content scope through the files public entry point. The reference is retained in plan evidence/acceptance and survives replacement/removal. No permanent-delete endpoint or ordinary runtime grant exists.
