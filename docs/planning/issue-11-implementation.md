## Behavior and design

Scheduling owns appointments, clinic duration/chair settings, command receipts and immutable dated history in Routes → Controller → Service → Repository. Central identity checks and writes share the existing clinic-serialized restricted-runtime transaction; scoped composite references and FORCE RLS cover all four new tables. Settings edits require intrinsic manager authority; scheduling and conflict override remain separately delegated permissions. Scheduling patient selection exposes only name/clinic number/ID without requiring personal-profile read or granting clinical access.

Book a dentist and optional named chair; omitted duration uses the current locked clinic default (initial30 minutes); explicit duration remains editable5–480 minutes. The four pilot chairs are editable defaults, not a patient/staff cap. Chair settings accept up to100 entries as bounded request validation. Patient search is an explicitly triggered name/number search returning50 results, with the refinement requirement visible. Archived patients cannot be newly booked or moved; existing appointment/history stays readable and cancellation remains possible.

Intervals are half-open. Booked, confirmed, arrived and in-care reserve dentist/chair; cancelled/no-show/completed free the slot. Concurrent overlapping writes serialize; only an explicit request with both manage and override permissions succeeds. UUID receipts bind payload and actor, returning original results after retries. Revisions reject stale changes. Nouakchott/UTC daily agenda includes cross-midnight overlaps. No cancellation fees or financial records are created.

Transitions: booked → confirmed/arrived/cancelled/no-show; confirmed → booked/arrived/cancelled/no-show; arrived → confirmed/cancelled; cancelled/no-show → booked with fresh resource conflict checks. Rescheduling permits booked/confirmed/arrived and retains prior times, durations, dentist/chair, status, actor/time and override evidence. Cancellation reason is optional. Walk-ins register directly arrived. In-care/completed are reserved for #15: starting clinical care must create the visit atomically and is deliberately unavailable as a scheduling-only action. Booking never creates a patient grant. `/appointments/suggestions` exposes the pre-catalog unavailable/empty interface and exported procedure-duration suggestion transport type; no invented catalog data.

Calendar dependency check: required current view is a dated agenda with dentist filtering, creation, details/history and date navigation via native date input. Accessible custom CSS/native controls meet that scope using approved tokens and existing React; no calendar dependency, external licensing or compatibility choice is introduced. Prototype calendar remains a visual reference, not a required paid library or all-view calendar implementation.

French interface uses RHF forms, TanStack Query server records and private in-tab state. Unknown request results freeze the exact UUID/payload and editor until same-command retry resolves; stale responses require explicit reconciliation. Stream invalidation is minimal and reauthorizes per event/heartbeat. Sensitive query data is cancelled/removed on unmount, with no browser persistence. Explicit cancellation and dirty-editor departure confirmation; saves await agenda refresh before enabling stale row selection. Settings revisions are frozen with original form inputs, and remote settings updates do not remount/discard drafts. Scoped fieldsets remove the existing generic240px scroll trap.
