## Implementation contract

- `apps/api/src/errors/app-error.ts` owns `AppError(status,message)`; its message must be safe for the caller. Backend features import it directly; identity no longer defines or re-exports an application-wide error.
- `installErrorHandling` registers the primary middleware and safe terminal handler after all routes. Express5 forwards rejected returned/awaited controller promises; no redundant async wrapper. AppError status/message, Zod400, P2002 conflict409 and body-parser400/413 preserve existing response shape `{error:string}` and French messages. Unexpected errors return generic500.
- `res.headersSent` logs a sanitized summary and calls next with the original error, forwarding to the safe terminal middleware, which closes the failed connection without the raw Express stderr fallback.
- Shared existing Pino logger is used by server startup and error middleware. Unexpected failures record a fixed event/message, HTTP method, server-registered route pattern (never concrete URL/parameters) and allowlisted error type. Unknown/unsafe exception names become Error. Never serialize raw exception/message/stack, cause, SQL, request body, query, cookies, authorization or session/patient data. This trades detailed exception diagnostics for the repository's confidentiality requirement; it is not a complete observability platform.
