## Transport contract

All routes use ready current authenticated sessions; POST uses existing Origin/CSRF protection. UUID inputs are canonicalized. Amount inputs are exact nonnegative decimal strings constrained by enabled currency precision; no rounding/conversion. Responses carry exact minor-unit strings. Shared inputs/types are in packages/contracts/src/index.ts.

| Route | Contract |
| --- | --- |
| `GET /api/billing/payment-methods` | Current clinic method revisions; manager or billing.edit. |
| `POST /api/billing/payment-methods` | Manager only: commandId, id, current revision (0 for new), nonempty name, active. Append revision, preserve old receipt names. Stale revision or changed command reuse: 409. No delete. |
| `POST /api/billing/:patientId/settlements` | commandId, enabled currency, methodId (active for new money, null for credit-only), newMoney, explicit deposit, allocations[{chargeId,newMoney,credit}]. Each nonempty allocation targets a visible started procedure charge in the same patient/currency. Sum allocation newMoney + deposit must equal newMoney received; no implicit excess. |
| `GET /api/billing/:patientId` | Adds settlements, separate deposits (original and available amount), per-charge paidMinor/chargedMinor/allocations. dueMinor is adjusted charge minus allocated funds. reconciliationRequired compares accepted price with adjusted charge, never with unpaid balance. Credit and debt stay separate in each currency. |
| `GET /api/billing/:patientId/settlements/:id` | Retained authorized settlement/receipt, unchanged by later allocations/method changes. billing.read. |
| `GET /api/billing/:patientId/settlements/:id/print` or `/download` | Structured French document data: title, immutable settlement, labels distinguishing new funds, old credit and separate deposit. Requires billing.read plus the corresponding financial.print/download grant; managers have full financial authority. Product rendering belongs to #57/#69. |

Each new-money command creates exactly one receipt for all newly received money, including its separately entered deposit. Receipts snapshot method name and patient/clinic identity. New and old funds are separate on every allocation; old sources link to retained settlements/receipts. Credit-only settlement has receiptNumber=null, no new receipt, and document title Affectation de crédit. Receipt series is independent clinic/UTC-year `REC-YYYY-NNNNNN`; sequence is derived from immutable issued receipts under the existing clinic treatment transaction lock, with database uniqueness as an additional guard. No new lock strategy or process-local counter. Failed transactions issue nothing; retained numbers are never reused. Invoice series remains #22.

Manager and explicitly permitted staff have general financial scope. Ordinary doctors require active patient access plus the action capability and may allocate new money only to their personally performed charges. Unassigned patient deposits/credit require general financial authority; doctors cannot view/spend that pool. Own-work charge allocation projections show their permitted payments even when a whole mixed receipt also includes other work; full mixed/unassigned receipts are withheld to avoid leaking other finances. Staff fields remain neutral references, identity, dates and money without procedure/tooth/clinical details. Historical-only/current revoked users cannot use these active endpoints. Authorization is rechecked before replay or output.

404 covers invisible patient/charge/settlement; 403 denied current capability/patient/own-work scope; 400 invalid precision/currency/method/empty allocation/repeated charge/unreconciled new-money total; 409 insufficient credit, overpayment, stale method revision or changed command replay. A persistence failure returns 500 and rolls back settlement, funds and command result atomically. Identical authorized retry returns the original result even if a method was later disabled or the year changed. Separate commands represent separate explicit receipts; the client must retain commandId across uncertain-response retries.

Accepted-price reconciliation cannot lower a charge below funds already allocated; explicit fund/charge correction remains #23. Existing financial records are append-only; no automatic refund, netting, invoice, clinical completion or patient-wide credit spending by doctors is introduced.
