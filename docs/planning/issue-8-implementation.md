## Result

Managers create individual doctor/staff identities with optional shared contact details, unlimited account counts, independent doctor eligibility/manager authority/login method, and individually configurable capabilities. Named workflows change username, permissions, doctor/staff profile, manager authority, account status and temporary password. Manager writes require current-password confirmation; actor authorization and target lookup/check/write share the same clinic transaction. A consistent clinic advisory lock precedes account locks and serializes last-configured-manager decisions. Every administrative write requires a loaded account revision; stale writes return 409 and require reconciliation. French forms preserve conflicting input until explicit reload/abandon.

Account IDs/history survive requested case-insensitive username changes. A clinic-scoped reservation table prevents reassignment of current/retired usernames to another account, including operator provisioning and migration backfill. Composite account references and FORCE RLS preserve clinic isolation. Account summaries never return password hashes, verification/recovery tokens or offline codes.

Initial/reset temporary credentials expire after 24 hours, require a distinct personal password, and are consumed atomically. Password changes/resets, disablement and account-type/authority changes invalidate every PC session on the next direct request. Permissions are resolved from current server state on every identity request. Promoted doctors retain clinic-code/username login, their doctor eligibility and restricted manager setup until verified recovery email and saved codes. Last active fully configured manager cannot be disabled/demoted or reset into incomplete setup by another manager. Recovery never restores disabled/historical-only accounts.

Managers recover with hashed single-use offline codes or 30-minute verified-email links. Replacing links invalidates predecessors; requests alone leave sessions active. Completion revokes sessions/old code batches and creates a restricted recovery session solely for verifying details and saving a fresh batch. A lost primary mailbox can be replaced only in explicit persisted recovery setup; original provisioning remains locked to its provisioned email. Other-manager recovery uses temporary credentials and the same restricted setup. Prior verification links are invalidated on reset. Ordinary email change requires current password, retains the old verified login until replacement verification, then revokes sessions. Old-mailbox notification is required before address replacement completes. Failed recovery delivery invalidates its token and returns the same generic accepted response as unknown accounts.

French browser forms support account creation, per-action grants, requested rename/reset, promotion, profile/status changes, personal password/email changes and anonymous manager recovery. Codes stay only in account-owned mounted memory and have explicit download/save confirmation. Server records remain TanStack Query; form values remain React Hook Form; no sensitive persistent browser store was introduced. The owner deferred visual design.
