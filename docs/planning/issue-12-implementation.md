## Behavior

Clinical Routes → Controller → Service → Repository persists medical history/allergies and manual FDI chart versions. Staff with active patient scope and relevant capability draft; doctors with relevant capability confirm another author's draft. The full current server draft, version, author, observation/recording dates and patient identity are displayed before explicit confirmation. Corrections append dated draft/final versions and retain previous finalized content while a correction is pending. Restricted runtime has SELECT/INSERT only on FORCE-RLS ClinicalRevision; composite clinic references and immutable snapshots preserve attribution/history. Clinical operations create no treatment, plan, procedure or charge: this is confirmed by module/code inspection, not a billing integration test (billing is not implemented here).

Clinical reads require clinical.read and active scope; draft/finalize commands require the relevant action plus clinical.read because their receipts contain clinical workspace content. clinical.history separately governs essential event history in reads and write/replay receipts; removing it cannot disclose old event contents through a saved receipt. Historical-only/disabled accounts, removed grants and capability changes are checked on subsequent direct requests. Explicit historical grants and cutoff selection belong to open #18, as confirmed by root against the live tracker. This slice stores immutable recordedAt/observedAt versions suitable for that later integration; it does not implement or claim historical-access delivery.

FDI is explicit, with valid permanent/primary/mixed positions and no age inference. Unassessed presence stays unknown. Presence/eruption, extraction history, coexisting conditions and existing crown/root-canal/implant treatments are independent. Valid whole-tooth/surface findings include Other with required note; anterior/posterior surface validation is authoritative on the server. Chart-wide optional Other notes describe special/supernumerary positions without fabricated normal FDI codes. French labels map outer to labial/buccal and inner to palatal/lingual. Manual charts do not imply diagnostic completeness or clinician/legal approval.

French forms use React Hook Form, in-memory command payloads and TanStack Query server cache, with local selection state and no persistent clinical cache. Ambiguous responses freeze editing/patient switching and expose a generic same-command retry, including finalize-only doctors. Conflicts retain local form values; explicit reconciliation loads the latest revision and visibly presents the entire remote draft before confirmation. Authorized discovery SSE surfaces new sharing before a patient is selected; patient-scoped SSE refetches and removes a revoked record. Notifications contain invalidation signals, not clinical content.
