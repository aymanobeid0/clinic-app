## Delivered behavior

A treatment feature exposes Routes → Controller → Service → Repository. Catalog management requires the separate explicit `catalog.manage` capability, even for managers. Managers may enable multiple verified currencies; financial authority does not permit clinical editing. Doctor-managers retain intrinsic financial override/discount authority but require clinical.read, plans.draft and active patient scope for proposals. Assigned/shared permitted staff may draft; non-doctor managers cannot open these clinical records. Ordinary doctors/staff require separately granted price override and discount capabilities. Retaining an existing authorized price/discount on an unrelated edit does not require those capabilities again; changing them does. Replaying an old financial command after losing its applicable capability is denied.

Catalog entries contain a default exact price, currency, duration and availability. Retirement preserves references. Existing entry currency cannot be relabeled. Five supported currencies are deliberately bounded to the directly verified ISO subset: MRU/EUR/USD precision2, JPY0, KWD3. Builder directly fetched the authoritative SIX ISO4217 list on2026-10-16, publication2026-09-17: https://www.six-group.com/dam/download/financial-information/data-center/iso-currrency/lists/list-one.xml (authority landing page https://www.six-group.com/en/products-services/financial-information/market-reference-data/data-standards.html). Root independently verified the same source. Other codes are rejected until verified; no currency/conversion service, rounding, implicit enable or arbitrary precision selection.

Amounts use validated decimal strings at input, bigint integer minor units for arithmetic/storage, and decimal strings for transport. Formatting also uses strings, never floating-point division. Per-item inputs allow up to15 whole digits and at most3 fractional digits; excess currency precision is rejected, including trailing fractional digits for JPY. Fixed exact discounts require a reason and cannot exceed the price; no percentage calculator silently rounds. Each proposal has one currency; balances/conversion/billing are outside #13.

Identified proposals contain versioned priced items with one-tooth, multiple-tooth or whole-mouth scope, valid FDI positions and no duplicate teeth/items. Server-owned snapshots retain the copied procedure name, default/overridden price, duration and discount evidence. Catalog changes do not rewrite any existing draft item. New items require the current catalog revision and active entry; stale selection is rejected for explicit review. Existing item identities cannot be reassigned to another catalog procedure. Plan identity is bound to one patient inside its clinic. Immutable revisions retain author/date and essential per-record history when currently authorized.

Clinic-scoped transactions, advisory serialization, optimistic revision checks and actor/payload-bound idempotent commands protect conflicting writes and retries. FORCE-RLS tables use restricted runtime grants and composite clinic foreign references; proposal revisions are INSERT/SELECT only. Old plan command receipts return currently authorized latest content, and cannot expose superseded titles/items after losing clinical.history. Active clinical grants/permissions are checked before replay. New tables are included in runtime owner-safety checks.

Appointment suggestions expose only procedure ID, label and duration to appointments.manage users; no catalog price projection. Applying a suggestion is explicit, duration remains manually editable, and catalog updates never mutate reservations. French catalog/proposal forms use React Hook Form input, TanStack Query server state and component-local UI selection; no persistent clinical browser storage or new dependency. Existing drafts autosave after initial explicit creation. In-flight/ambiguous responses lock editing and patient/plan switching and preserve the exact command for retry. Conflicts retain input and expose remote rereading with visible reread failures. Patient identity stays visible in the enclosing clinical dossier; plan IDs/versions and exact currency totals are visible in proposal summaries/history. Current-tab drafts are intentionally not cross-restart offline storage.

SSE invalidations remain authorized and content-free. Discovery handles newly shared patients before selection; revocation removes open proposals. Catalog changes refresh current choices. Manager-only currency settings have a separate authorized stream, mounted with the opened currency settings view; unopened settings do not multiply requests during unrelated patient workflows. Server rate limits were retained.
